# 开源政策

本政策说明 Feedback Agent 公开哪些内容、采用什么许可证，以及维护者、贡献者和
部署者分别需要承担什么责任。它是项目治理说明，不构成法律意见。

## 目标

开源的首要目标是降低 Flutter/Web 产品接入用户反馈智能体的成本，形成可复用的
自托管方案和真实接入案例。当前优先级是采用率、可审计性和安全默认值，而不是
限制其他团队商用。

## 许可证选择

项目原创代码使用 Apache License 2.0，原因是：

- 允许使用、修改、分发、私有部署和商业使用；
- 明确提供贡献者可授予范围内的专利许可；
- 要求保留许可证、NOTICE 和必要署名；
- 不强制使用者公开自己的业务代码，企业采用阻力较低；
- 不提供质量、适用性或持续支持保证。

Apache-2.0 授予已经取得副本的使用者持续权利，之后把仓库改为私有或更换未来
版本的许可证，不能撤回已经授出的旧版本许可。

其他选择的取舍：

| 方案                        | 适用情况                       | 当前不选择的原因                                      |
| --------------------------- | ------------------------------ | ----------------------------------------------------- |
| MIT                         | 追求最短许可证文本             | 缺少 Apache-2.0 那样明确的专利条款                    |
| AGPL-3.0                    | 希望网络服务修改也必须提供源码 | 会增加 SaaS 和企业接入顾虑，不利于初期采用            |
| 商业限制或 source-available | 希望禁止竞品托管或限制商用     | 不符合 OSI 意义上的开源，不能再把项目称为标准开源软件 |

如果未来要提供闭源企业增强版，可以把新增、完全自有的模块放在独立仓库和独立
许可证下；已经以 Apache-2.0 发布的代码仍保持原许可。

## 可以公开的内容

- apps、packages 中的项目源代码和测试；
- Prisma Schema、迁移和不含真实数据的种子；
- Dockerfile、Compose 与通用部署模板；
- .env.example 和 .env.production.example 等纯占位模板；
- 架构、API、接入、备份和贡献文档；
- pnpm 锁文件、Flutter 示例工程和合法可分发的项目资产。

## 不能进入公开仓库的内容

- .env、.env.production、云账号凭据、模型 Key、JWT Secret、App Secret、
  私钥、证书私钥、签名文件和 SSH 配置；
- 生产数据库、MinIO 对象、Redis 数据、备份、日志、错误转储和监控导出；
- 用户对话、邮箱、设备标识、附件、内部需求、未脱敏截图和客服记录；
- 真实服务器 IP、内部拓扑、未公开域名、运维账号和应急操作记录；
- 无明确再分发权的字体、图片、Logo、设计源文件或第三方代码；
- 客户专属提示词、知识库、模型账号和商业配置。

即使文件已从当前目录删除，只要曾进入 Git 历史，也必须先重写历史并轮换相关
凭据，再公开仓库。

## 第三方代码

apps/admin 派生自 MIT 许可的 pure-admin-thin，必须保留
apps/admin/LICENSE 中的原始版权和许可文本。其他依赖继续使用各自许可证，
详情见 THIRD_PARTY_NOTICES.md。构建并分发容器镜像时，应保留镜像内依赖的
许可证文件，并基于发布锁文件重新生成依赖许可证清单。

## 数据与模型责任

开源许可证只覆盖软件，不授予任何用户数据、客户知识库、模型账号、品牌素材或
第三方内容的权利。部署者负责取得数据处理授权、设置保留期限、响应删除请求，
并遵守所选模型服务商和云服务商的条款。

## 贡献与治理

- 贡献默认按 Apache-2.0 提交，不要求初期贡献者签署 CLA；
- 重大架构、Schema、认证和隔离边界变更先通过 Issue 讨论；
- 安全漏洞通过 GitHub 私密漏洞报告处理，不在公开 Issue 披露；
- main 分支代表当前开发状态，稳定版本后再通过语义化版本和 Release 发布；
- 维护和答疑采用 best-effort，不承诺 SLA。

如果未来需要双重许可、企业 CLA、商标政策或付费托管条款，应在接受外部大规模
贡献前单独评估，避免权利归属不清。
